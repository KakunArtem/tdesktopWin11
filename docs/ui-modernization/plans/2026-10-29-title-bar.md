# Title Bar Implementation Plan (C8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the custom title area part of the window material, as in the exploration's 32 px transparent title bar, while keeping Telegram's caption buttons, drag regions, snap layouts, system menu and inactive state.

**Architecture:** The forked `lib_ui` gains one hook: a window can supply a painter for its custom title background. When none is set the title paints exactly as upstream. The app sets the hook to the Window role while material is active, hides the title shadow under Soft Panels, and adds the title colors to C3's readability adjustments.

**Tech Stack:** C++20, Qt 6.11, forked `lib_ui` (`ui/platform/win/`, `ui/widgets/rp_window*`), Win32 non-client handling.

**Spec:** [architecture.md, C8](../architecture.md#components); exploration CSS `.titlebar` (height 32 px, no own background); roadmap Phase 3.

**Visual reference:** [C8 title bar](../component-references/c8-title-bar/README.md): the mockup title, night theme states with caption glyph contrast, and the caption button hovers. Its findings correct Task 2 Steps 2 and 3.

**Depends on:** [toolkit fork](2026-10-29-toolkit-fork.md), [shell layout](2026-10-29-shell-layout.md), [material fills](2026-10-29-material-fills.md).

## Global Constraints

- All [ground rules](README.md#ground-rules), including the `lib_ui` recheck rule.
- `lib_ui` change: one additive API; with no painter set, upstream behavior is byte-for-byte unchanged.
- Title height stays Telegram's style value; this plan does not resize the title.
- Caption buttons keep their hover and pressed colors; the close button keeps its red hover.
- Native frame on: material is refused (C2), so the hook is never set.

## Pinned-source corrections during implementation

Rechecked on 2026-11-05. The Windows helper keeps the same `TitleWidget`
when native framing changes; it only hides or shows it. Keep the painter in
that persistent widget and forward through the helper. Other platforms
ignore the opt-in method without changing their title painting.

`defaultWindowTitle` also paints opaque resting backgrounds inside each
caption icon, and `TitleWidget` owns its own `PlainShadow`. The app's
native-frame-only `_titleShadow` is a different object. Use parallel app
title styles: a shadow-free Soft Panels title and a material variant with
glyph-only resting icons. Retain the original hover and pressed icons.
Choose the style on material and Soft Panels changes and restore the
upstream style with both off. Test the caption-button edges and bottom row,
in addition to the open title area.

The pinned style generator rejects inheritance of anonymous icons from
another module and the attempted dotted field copies. The app therefore
copies `st::defaultWindowTitle` into its two title variants in C++, using
generated glyph-only icons from `window_soft_panels.style`. Unchanged
geometry, hover and pressed fields come from the upstream style.

Desktop correction, 2026-11-06: a translucent title reveals what Windows draws
under it, so the toolkit also hides the native caption while a painter is set.
See [the checks](../checks/title-bar.md#native-caption-under-the-translucent-title).
This goes beyond the one additive API in the Global Constraints.

**Interfaces:**
- Produces, in `namespace Ui`: `void RpWindow::setTitleBackgroundPainter(Fn<void(QPainter&, const QRect&)> painter);` — forwards to the platform helper, which forwards to its title widget; an empty `Fn` restores upstream painting.

- [x] **Step 1: Recheck the call path at the pinned commit**

Read `RpWindow`, the platform window helper it owns, and the Windows title widget's `paintEvent`. The [preflight](../preflight.md) found at `79c846fd` that `TitleWidget::paintEvent` in `ui_window_title_win.cpp` fills the whole widget with the `WindowTitle` style's `bgActive` or `bg`, chosen by `window()->isActiveWindow()`; confirm it is unchanged. - [x] **Step 2: Implement the hook**

Store the painter in the persistent title widget, clear its opaque-paint promise while set, and restore that promise when the painter is cleared. Other platforms ignore the method. Verify frame toggles retain the painter and an empty painter restores the original raster.

### Task 2: Material title in the app

**Files:**
- Modify: `Telegram/SourceFiles/platform/win/main_window_win.cpp`
- Modify: `Telegram/SourceFiles/window/main_window.cpp`
- Modify: `Telegram/SourceFiles/window/window_material.cpp` (C3's adjusted-entry list)
- Modify: `Telegram/SourceFiles/window/window_soft_panels.style`
- Modify: `Telegram/SourceFiles/ui/controls/title_sub_widget.cpp`

- [x] **Step 1: Set the painter**

In `MainWindow::initHook()` on Windows, when `Window::Material::Capable()`, call `setTitleBackgroundPainter` with a painter that calls `PaintSurface(p, rect, Surface::Window, solid)`, where `solid` is `st::titleBgActive` while the window is active and `st::titleBg` otherwise, as upstream chooses. Both exist in `lib_ui/ui/colors.palette`; a theme may set them apart. Repaint the window title on `FillsChanged()`.

- [x] **Step 2: Title shadow**

Leave the app's `_titleShadow` unchanged: `MainWindow::refreshTitleWidget` creates it only with the native frame, which refuses material. Suppress the toolkit's separate shadow through the parallel title styles described above, and remove resting caption-icon backgrounds while material is active. Re-evaluate the style on `ActiveValue()` and `SoftPanelsValue()` changes; keep the existing hover and pressed treatment.

- [x] **Step 3: Title text readability**

Add the caption glyph entries `titleButtonFg`, `titleButtonFgActive`, `titleButtonCloseFg` and `titleButtonCloseFgActive` to C3's adjusted-entry list with the icon target 3:1, measured against the Window role floor. On Windows, `titleFg` and `titleFgActive` color only the canary build label; add them too at 4.5:1, and paint that label's own background through `PaintSurface` ([finding](../component-references/c8-title-bar/README.md#findings-from-the-source)).

- [ ] **Step 4: Build and check**

With material on: the title shows the backdrop at the Window fill, continuous with the gaps; with material off: identical to before. Toggle night mode: the title follows.
