# Title Bar Implementation Plan (C8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the custom title area part of the window material, as in the exploration's 32 px transparent title bar, while keeping Telegram's caption buttons, drag regions, snap layouts, system menu and inactive state.

**Architecture:** The forked `lib_ui` gains one hook: a window can supply a painter for its custom title background. When none is set the title paints exactly as upstream. The app sets the hook to the Window role while material is active, hides the title shadow under Soft Panels, and adds the title colors to C3's readability adjustments.

**Tech Stack:** C++20, Qt 6.11, forked `lib_ui` (`ui/platform/win/`, `ui/widgets/rp_window*`), Win32 non-client handling.

**Spec:** [architecture.md, C8](../architecture.md#components); exploration CSS `.titlebar` (height 32 px, no own background); roadmap Phase 3.

**Visual reference:** [C8 title bar](../component-references/c8-title-bar/README.md): the mockup title, night theme states with caption glyph contrast, and the caption button hovers. Its findings correct Task 2 Steps 2 and 3.

**Depends on:** [toolkit fork](2026-10-29-toolkit-fork.md), [shell layout](2026-10-29-shell-layout.md), [material fills](2026-10-29-material-fills.md).

## Global Constraints

- All [ground rules](README.md#ground-rules), including the `lib_ui` recheck rule.
- `lib_ui` change: one additive API; with no painter set, upstream behavior is byte-for-byte unchanged.
- Title height stays Telegram's style value; this plan does not resize the title.
- Caption buttons keep their hover and pressed colors; the close button keeps its red hover.
- Native frame on: material is refused (C2), so the hook is never set.

## Review Focus

- Hovering the maximize button on Windows 11: the snap layouts flyout must still appear. Pinned by Task 3 Step 2.
- Double-click on the title to maximize and restore, drag to move, Alt+Space system menu: unchanged. Pinned by Task 3 Step 3.
- Window inactive (another app focused): title text dims as before and stays readable on the material. Pinned by Task 3 Step 4.
- Night mode switch: the title repaints with the new fill without hover. Pinned by Task 2 Step 3.
- Title shadow: hidden under Soft Panels, unchanged without. Pinned by Task 2 Step 2.

### Task 1: Title background hook in the `lib_ui` fork

**Files (in the `lib_ui` fork, branch from `.gitmodules`):**
- Modify: `ui/widgets/rp_window.h`, `rp_window.cpp`
- Modify: `ui/platform/ui_platform_window.h` and the Windows title widget in `ui/platform/win/ui_window_title_win.{h,cpp}`

**Interfaces:**
- Produces, in `namespace Ui`: `void RpWindow::setTitleBackgroundPainter(Fn<void(QPainter&, const QRect&)> painter);` — forwards to the platform helper, which forwards to its title widget; an empty `Fn` restores upstream painting.

- [ ] **Step 1: Recheck the call path at the pinned commit**

Read `RpWindow`, the platform window helper it owns, and the Windows title widget's `paintEvent`. Record in the commit description which function fills the title background (the roadmap names `ui_window_title_win.cpp`). If the Windows title is drawn in the non-client area by `ui_window_win.cpp` instead, apply Step 2 there.

- [ ] **Step 2: Implement the hook**

In the title widget's paint, call the painter for the background rectangle when it is set, otherwise fill as now. Store the painter in the helper so a title widget recreated on frame changes receives it again. Platforms other than Windows store and ignore it.

### Task 2: Material title in the app

**Files:**
- Modify: `Telegram/SourceFiles/platform/win/main_window_win.cpp`
- Modify: `Telegram/SourceFiles/window/main_window.cpp`
- Modify: `Telegram/SourceFiles/window/window_material.cpp` (C3's adjusted-entry list)

- [ ] **Step 1: Set the painter**

In `MainWindow::initHook()` on Windows, when `Window::Material::Capable()`, call `setTitleBackgroundPainter` with a painter that calls `PaintSurface(p, rect, Surface::Window, st::titleBg)`. Repaint the window title on `FillsChanged()`. Recheck the title palette name (`titleBg`) in `lib_ui/ui/colors.palette`.

- [ ] **Step 2: Title shadow**

In `Window::MainWindow::updateControlsGeometry`, hide `_titleShadow` while `SoftPanels()`; show it otherwise. Re-run geometry on `SoftPanelsValue()` changes. `MainWindow::refreshTitleWidget` creates `_titleShadow` only with the native frame, which refuses material, so first confirm whether this step changes anything and skip it if not ([finding](../component-references/c8-title-bar/README.md#findings-from-the-source)).

- [ ] **Step 3: Title text readability**

Add the caption glyph entries `titleButtonFg`, `titleButtonFgActive`, `titleButtonCloseFg` and `titleButtonCloseFgActive` to C3's adjusted-entry list with the icon target 3:1, measured against the Window role floor. On Windows, `titleFg` and `titleFgActive` color only the canary build label; add them too at 4.5:1, and paint that label's own background through `PaintSurface` ([finding](../component-references/c8-title-bar/README.md#findings-from-the-source)).

- [ ] **Step 4: Build and check**

With material on: the title shows the backdrop at the Window fill, continuous with the gaps; with material off: identical to before. Toggle night mode: the title follows.

- [ ] **Step 5: Commit**

```bash
git add Telegram/SourceFiles/platform/win/main_window_win.cpp Telegram/SourceFiles/window/main_window.cpp Telegram/SourceFiles/window/window_material.cpp
git commit -m "Painted the title bar with the window material."
```
